# TradingView integration

Open the local dashboard, unlock it, and choose **TradingView** in the sidebar.

- **MES1! / MNQ1!** open the continuous futures charts directly on TradingView. Data access
  and delay depend on TradingView and the user's exchange permissions. These symbols do not
  select or replace the exact expiring contracts configured for paper execution.
- **Market context chart** embeds TradingView's hosted Advanced Chart widget for SPY or QQQ.
  Select an ETF and starting interval, then choose **Load TradingView chart**. Use the
  widget's chart tools for research. No widget API key or account is configured in this app.
- **Close chart**, changing dashboard pages, or locking the workspace removes the external
  frame. Changing the ETF or starting interval replaces a loaded frame; drawings may reset.
- If the chart stays blank or reports unavailable data, choose **Open on TradingView**.
  External availability, browser blocking and TradingView data permissions remain outside
  the local app's control. A requested or loaded frame is not proof of fresh market data.

## What this provides

TradingView [does not offer a public API for retrieving prices or indicator values](https://www.tradingview.com/support/solutions/43000474413-i-need-access-to-your-api-in-order-to-get-data-or-indicator-values/).
Its broker REST integration is for brokers implementing connectivity to TradingView; it is
not a market-data API key for this bot. The Advanced Charts Datafeed API connects a chart to
[data you supply](https://www.tradingview.com/charting-library-docs/latest/connecting_data/).

The free widget's [published North American markets](https://www.tradingview.com/widget-docs/markets/north-america/)
do not include CME futures. The embedded choices are explicitly **SPY and QQQ ETFs**; neither
is an MES/MNQ quote or interchangeable with a futures price. Delays and symbol availability
are governed by TradingView. A paid TradingView account does not upgrade widget data; see
the [widget data FAQ](https://www.tradingview.com/widget-docs/faq/data/).

For quotes used by the paper engine and the local Overview chart, configure authorized
[T4 simulator access or an external adapter](MARKET_DATA.md). The widget never contributes
quotes, indicators, orders, fills, account marks, or readiness to that engine. The local
dashboard unlock key is separate from every provider credential.

## Implementation and isolation

`wwwroot/tradingview-reference.js` creates the separate-origin iframe URL generated by
TradingView's [official Advanced Chart embed script](https://s3.tradingview.com/external-embedding/embed-widget-advanced-chart.js),
using only allowlisted symbols/intervals and fixed public display options. The source was
checked against the official embed on 2026-10-04. This is the hosted widget, not a bundled
copy of the separately licensed Advanced Charts library. TradingView attribution remains
visible below the chart. Official [widget configuration](https://www.tradingview.com/widget-docs/widgets/charts/advanced-chart/)
and [embedding documentation](https://www.tradingview.com/widget-docs/tutorials/iframe/build-page/widget-integration/)
describe the supported options.

The remote embed script is **not** executed in the local dashboard document. Only
`https://www.tradingview-widget.com` is permitted for frames by the dashboard's CSP. Local
scripts and API connections remain same-origin; framing the dashboard itself is prohibited.
The frame is sandboxed with scripts, its own remote origin and popups permitted, without
top navigation or form submission privileges. No dashboard/provider keys, account state,
local page URLs, referrer, or authenticated request headers are sent to it. TradingView
receives normal browser network information when the user loads its chart. There is no
quote scraping, local-API proxy, or postMessage bridge to paper controls.

The Overview chart continues to use locally hosted Lightweight Charts and provider data;
it works independently of this external reference page.

## Verification

`node scripts/test-tradingview.cjs` checks allowed URLs/inputs, absence of credentials in
embed configuration, frame isolation attributes, symbol switching and unloading. The HTTP
smoke tests verify CSP, local assets, and rejection of TradingView-origin API requests.
These tests do not establish TradingView chart rendering or exchange availability in a
real browser; manually check both ETF choices and the futures links in your environment.
